## Уровень A. Границы решений на make_moons

300 объектов, `noise=0.25`, признаки стандартизованы (SVM основан на расстояниях).

![Сводка](images/grid.png)

| Модель | accuracy (обучение) | Опорных векторов |
|---|---|---|
| linear, C=1 | 0,860 | 101 |
| rbf, C=1 | 0,910 | 92 |
| rbf, C=0,01 | 0,870 | 300 |
| rbf, C=100 | 0,937 | 57 |

Здесь accuracy посчитана **на обучающей выборке**: цель уровня — показать форму границы, а не сравнить качество. Рост 0,910 → 0,937 при C=100 нельзя считать улучшением модели: по картинке видно, что граница изгибается под отдельные точки.

**Выводы**

- Линейная граница не может обойти «полумесяцы», RBF-ядро даёт нелинейную границу без явного перехода в другое пространство.
- Малое C (0,01): все 300 объектов стали опорными, граница очень гладкая, штраф за ошибки мал — тенденция к недообучению.
- Большое C (100): граница сложная, опорных векторов мало (57), ошибка на обучении минимальна — риск переобучения.
- Положение границы определяют только опорные векторы (обведены кружками).

## Уровень B. Отток абонентов: подбор и сравнение

Разбиение train/test 80/20 со стратификацией. Весь препроцессинг (OneHot для `region`, `tariff`, стандартизация числовых) находится **внутри пайплайна**, поэтому в кросс-валидации нет утечки. Столбец `subscriber_code` (идентификатор) исключён из признаков. Подбор: `GridSearchCV`, 5-fold стратифицированная CV, метрика ROC-AUC, сетка `C ∈ {0,1; 1; 10; 100}` × `gamma ∈ {0,001; 0,01; 0,1; 1}`.

Лучшие параметры: `C=10, gamma=0,001`, AUC на CV = 0,777.

Средний AUC по кросс-валидации (строки — C, столбцы — gamma):

| C \ gamma | 0,001 | 0,01 | 0,1 | 1 |
|---|---|---|---|---|
| 0,1 | 0,771 | 0,772 | 0,763 | 0,655 |
| 1 | 0,774 | 0,776 | 0,745 | 0,655 |
| 10 | **0,777** | 0,761 | 0,694 | 0,646 |
| 100 | 0,774 | 0,739 | 0,646 | 0,646 |

Сравнение на отложенной тестовой выборке (использована один раз):

| Модель | F1 | ROC-AUC |
|---|---|---|
| SVM rbf (лучшая из сетки) | 0,599 | 0,801 |
| SVM linear, C=1 | 0,599 | 0,798 |
| Логистическая регрессия | 0,611 | 0,806 |
| Случайный лес | 0,556 | 0,752 |
| XGBoost | 0,586 | 0,792 |

**Выводы**

1. Настройка важна: при `gamma=1` AUC падает до 0,65 — это переобучение (большая gamma = малый радиус влияния объекта). Ненастроенный SVM с произвольными параметрами дал бы заметно худший результат.
2. Лучшая ячейка сетки — `gamma=0,001`, то есть **край сетки**. Значит, оптимум может лежать ещё левее; корректный следующий шаг — расширить сетку в сторону меньших gamma. Это ограничение работы.
3. AUC на CV (0,777) ниже, чем на тесте (0,801). Разница в пределах разброса оценки: тест — 600 объектов, оценка шумная. Оценка из GridSearchCV — это максимум из 16 вариантов и в общем случае оптимистична (Лекция 14); честной считается именно тестовая.
4. Различия между SVM (rbf и linear), логистической регрессией и XGBoost малы (AUC 0,79–0,81) и вряд ли значимы на 600 тестовых объектах; одним разбиением ранжирование моделей не доказать. Для строгого вывода нужна кросс-валидация с оценкой разброса.
5. Нелинейность в этих данных почти не нужна: линейный SVM и логистическая регрессия не хуже RBF. Это согласуется с замечанием лекции: RBF не всегда лучше линейного ядра.
6. Случайный лес оказался слабее остальных (AUC 0,752) при параметрах по умолчанию; он не настраивался, поэтому вывод о превосходстве SVM над лесом делать нельзя.

## Уровень C. Ограничения на больших выборках

`make_classification`, 20 признаков, параметры по умолчанию:

| n | rbf SVC, с | LinearSVC, с |
|---|---|---|
| 2000 | 0,03 | 0,00 |
| 4000 | 0,10 | 0,00 |
| 8000 | 0,61 | 0,01 |
| 16000 | 1,64 | 0,03 |

При удвоении n время rbf-SVC растёт в 3–6 раз (быстрее линейного закона), у LinearSVC — примерно линейно и на порядки меньше. Экстраполяция к сотням тысяч объектов делает RBF-SVC практически неприменимым, что подтверждает практическое ограничение из Лекции 11. Если данные близки к линейно разделимым или признаков очень много, линейный SVM — разумная замена. Времена — с одной машины и одного прогона, это порядок величины, а не точные константы.

## Ответы на вопросы для самоконтроля

1. **Почему максимальный зазор?** Граница, проходящая близко к обучающим объектам, чаще ошибается на новых данных, слегка отличающихся от обучающих; широкий зазор устойчивее.
2. **Что будет при удалении не-опорных объектов?** Модель не изменится: границу определяют только опорные векторы.
3. **Как C влияет на зазор и переобучение?** Большое C — узкий зазор, сложная граница, риск переобучения; малое C — широкий зазор, простая граница, риск недообучения (см. уровень A).
4. **Идея ядрового перехода.** Явного перехода в пространство большей размерности не происходит: считаются только скалярные произведения через ядро, поэтому нелинейная граница получается дёшево.
5. **Ограничения на больших выборках.** Время обучения растёт нелинейно с n (уровень C); вероятности требуют дополнительной калибровки и ещё большего времени. Плюс обязательное масштабирование и чувствительность к C и gamma.
